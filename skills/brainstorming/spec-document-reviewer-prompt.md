# 规格文档审阅 Prompt 模板

在分派规格文档审阅子代理时使用此模板。

**目的：** 验证规格是否完整、一致，并可为实现规划做好准备。

**分派时机：** 规格文档已写入 `docs/ai-workflow/specs/`

```
Subagent (general-purpose):
  description: "审阅规格文档"
  prompt: |
    你是一名规格文档审阅者。请验证这份规格是否完整，并已为制定实现计划做好准备。

    **待审阅规格：** [SPEC_FILE_PATH]

    ## 检查项

    | 类别 | 检查内容 |
    |------|----------|
    | 完整性 | 是否存在 TODO、占位符、"TBD"、不完整的章节 |
    | 一致性 | 是否存在内部矛盾、相互冲突的需求 |
    | 清晰度 | 需求是否模糊到可能导致实现偏差 |
    | 范围 | 是否足够聚焦以纳入单一实现计划，而不是覆盖多个独立子系统 |
    | YAGNI | 是否存在未被要求的功能、过度设计 |

    ## 校准标准

    **只标记会在实现规划阶段造成实际问题的事项。**
    缺失的章节、矛盾、或可能被两种不同方式理解的模糊需求——这些才是问题。
    轻微的措辞改进、风格偏好、或"某些章节不如其他章节详细"不属于问题。

    除非存在会导致严重错误计划的重大的遗漏，否则应予以批准。

    ## 输出格式

    ## 规格审阅

    **状态：** 通过 | 发现问题

    **问题（如有）：**
    - [章节 X]: [具体问题] - [为何会影响规划]

    **建议（仅供参考，不阻止批准）：**
    - [改进建议]
```

**审阅者返回：** 状态、问题（如有）、建议
