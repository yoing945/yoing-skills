# 索引核验规则（check-nav）

`check-nav` 子命令核验范围内 `AGENTS.md` **文档导航**章节的层级引用关系。它是对现有索引的核验与修补，不是重新生成：以各文档导航章节中已有的链接为事实来源逐层递进核验，只修补不一致的条目。

## 行为模式

- **默认只核验**：输出逐文档差异报告，不写入任何文件。
- **`--fix`**：核验并写入修补。仅修补报告中列出的不一致条目。

## 范围原则

核验范围完全由文档引用决定：从起始目录 `AGENTS.md` 的导航章节出发，链接指到哪就核验到哪，不做引用之外的任何探测（不枚举目录、不搜索未引用的文档）。引用显式指向哪里（包括嵌套仓库内的文档）都正常跟随核验；从未被任何导航引用的文档不在核验范围内——建立索引是生成流程的职责。

**禁止发起不带具体路径的探测调用**——如无路径的 `Glob **/AGENTS.md`、未限定 `path` 的全仓库 Grep——这类调用就是引用之外的探测。

唯一允许的文件系统操作是**存在性检查**：

- 验证链接目标文件是否真实存在（失效链接判定）；
- 检查链接路径的中间目录是否已存在 `AGENTS.md`（越级判定）。

## 核验的引用关系

对每个被引用触达的 `AGENTS.md`，其导航章节应当：

- 索引到**下一模块边界**为止——链接路径的中间目录若已存在 `AGENTS.md`，该条目即为越级，应移除并确认中间层 guide 已索引它
- 链接目标真实存在——失效链接移除
- 同一文档不被多级重复索引

## 执行流程

1. 确定起始目录：无 `path` 时为项目边界根目录。
2. 读取起始目录 `AGENTS.md` 的导航章节，得到第一层链接。
3. 沿链接逐层递进：直接 Read 每个被索引 guide 的文件——Read 同时完成存在性确认与导航章节获取（文件过大时才改用 Grep 定位章节后局部读取，且 Grep 的 `path` 必须指向该具体文件）。按「核验的引用关系」逐条核验。条目的名称与说明文字以导航章节现有内容为准，不重新分析被索引文档的内容。
4. 输出逐文档差异报告：新增、移除、层级调整的条目；`--fix` 时同时写入修补。

## 约束

- 只修补导航章节中不一致的条目；保留条目的现有名称与说明文字；文档其余章节（目录结构、自定义章节）一律不动。
- 不为缺失的目录新建 `AGENTS.md`。核验中若发现已存在的 guide 未索引其下被越级引用的模块，属于链路断裂，应报告，`--fix` 时按 [`docs-navigation`](docs-navigation.md) 规则补建/补全其导航章节。
- 不调用扫描脚本（`run.py`），核验不依赖任何目录扫描。
