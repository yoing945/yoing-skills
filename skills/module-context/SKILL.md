# 模块上下文获取

深入了解项目中某个具体模块的文档、源码和依赖关系，为基于该模块的开发或修改建立精确上下文。

## 触发场景

- 用户要求了解某个具体模块的实现细节
- 用户需要在某个模块上开发新功能或修复 bug
- 用户问"xxx 模块是怎么实现的"、"给我讲讲 yyy 模块"等
- 当前任务涉及对特定模块的代码修改

## 执行步骤

### 步骤1：读取项目指南文件

按优先级查找并阅读项目指南：`AGENTS.md` (或`CLAUDE.md`)→  → `README.md` → 概览项目目录结构。

### 步骤2：读取项目记忆文件

查找并阅读项目级记忆文件：

1. 查找 `.agents/`(或`.claude/`) 目录下 `memory/` 子目录中的内容；以及该目录`AGENTS.md` (或`CLAUDE.md`)
2. 若记忆文件过多，优先读取最新修改的文件；若内容过长，优先读取摘要性内容

### 步骤3：确定目标模块

**若用户已告知模块名**：
- 在项目目录中主动探索，通过目录结构、文件名、文档索引等方式定位该模块
- 若存在歧义（如多个同名目录），向用户确认具体位置

**若用户未告知模块名**：
- 从步骤1读取到的文档索引中提取模块相关条目
- 向用户列出可选模块，请用户选择目标模块

### 步骤4：读取模块文档与源码

定位到模块目录后：

1. **阅读模块文档**：如果模块根目录存在 `.md` 文档（如 `<模块名>.md`、`README.md` 等），优先阅读
2. **阅读源码**：浏览模块内的核心源码文件（入口文件、主要逻辑文件、对外接口文件），了解模块的职责边界、关键类/函数和实现逻辑，优先阅读摘要性内容和核心接口，不陷入实现细节

### 步骤5：加载模块依赖（可选）

1. 查找模块目录下的 `.agent.context*.md` 文件，优先级：`.agent.context.local.md` > `.agent.context.md`
2. 若存在，解析其中的依赖项目/模块名称及本地路径
3. 为每个已配置路径的依赖并行启动subagent，执行简化版上下文获取（只读指南文件和模块文档，不深入源码，不读记忆文件）
4. 整合subagent 的输出，留待步骤6整合

若 `.agent.context*.md` 不存在且无依赖声明，跳过此步骤。

### 步骤6：整合输出

向用户输出模块上下文摘要，包含：

- **模块定位**：该模块在项目中的位置和职责边界
- **项目上下文摘要**：基于步骤1-2的项目级关键信息（技术栈、编码规范等）
- **模块文档要点**：模块文档中的关键约定和结构
- **源码关键信息**：核心类/函数、入口点、关键逻辑概述
- **依赖上下文**（如有）：已加载的依赖模块/项目的核心信息
- **注意事项**：模块的特殊约定、已知坑点

输出应精炼、无冗余，聚焦模块本身。信息量大时分段条理呈现。

## 验证标准

- [ ] 已读取项目级指南和记忆文件
- [ ] 已确定并定位目标模块
- [ ] 已阅读模块文档和核心源码
- [ ] 若存在依赖，已询问用户并加载指定依赖（或已跳过）
- [ ] 向用户提供了模块上下文摘要
