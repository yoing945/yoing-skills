# 模块上下文获取

深入了解项目中某个具体模块的文档、源码和依赖关系，为基于该模块的开发或修改建立精确上下文。

## 触发场景

- 用户要求了解某个具体模块的实现细节
- 用户需要在某个模块上开发新功能或修复 bug
- 用户问"xxx 模块是怎么实现的"、"给我讲讲 yyy 模块"等
- 当前任务涉及对特定模块的代码修改

## 执行步骤

### 步骤1：读取项目指南文件

按优先级查找并阅读项目指南：`AGENTS.md` → `CLAUDE.md` → `README.md` → 概览项目目录结构。

### 步骤2：读取项目记忆文件

查找并阅读项目级记忆文件：

1. 查找 `.claude/` 目录下所有文件，尤其是 `memory/` 子目录中的内容
2. 查找 `.agents/` 目录下所有文件，尤其是 `memory/` 子目录中的内容
3. 查找其他可能存放项目级记忆的位置（如项目根目录下的 `.memory/`、`docs/memory/` 等）
4. 若记忆文件过多，优先读取最新修改的文件；若内容过长，优先读取摘要性内容

### 步骤3：确定目标模块

**若用户已告知模块名**：
- 在项目目录中主动探索，通过目录结构、文件名、文档索引等方式定位该模块
- 若存在歧义（如多个同名目录），向用户确认具体位置

**若用户未告知模块名**：
- 从步骤1读取到的文档索引中提取模块相关条目
- 向用户列出可选模块，请用户选择目标模块

### 步骤4：读取模块文档与源码

定位到模块目录后：

1. **阅读模块文档**：如果模块根目录存在 `.md` 文档（如 `AGENTS_xxx.md`、`README.md` 等），优先阅读
2. **阅读源码**：浏览模块内的核心源码文件（入口文件、主要逻辑文件、对外接口文件），了解模块的职责边界、关键类/函数和实现逻辑
3. 若模块文档或源码信息量大，优先阅读摘要性内容和核心接口，不陷入实现细节

### 步骤5：加载模块依赖（可选）

如果模块文档中列出了依赖项目或依赖模块：

1. 向用户提问："该模块依赖以下项目/模块：[A, B, ...]。需要加载哪些的上下文？请按 `名称: 本地路径` 的格式列出，不需要则回复'无'。"
2. 用户指定后，为每个依赖并行启动子 agent
3. 子 agent 按 module-context 步骤1-4执行简化版上下文获取（只读指南文件和模块文档，不深入源码，不读记忆文件）
4. 主 agent 收集各子 agent 的输出，留待步骤6整合

若用户回复"无"或模块文档中无依赖声明，跳过此步骤。

### 步骤6：整合输出

向用户输出模块上下文摘要，包含：

- **模块定位**：该模块在项目中的位置和职责边界
- **项目上下文摘要**：基于步骤1-2的项目级关键信息（技术栈、编码规范等）
- **模块文档要点**：模块文档中的关键约定和结构
- **源码关键信息**：核心类/函数、入口点、关键逻辑概述
- **依赖上下文**（如有）：已加载的依赖模块/项目的核心信息
- **注意事项**：模块的特殊约定、已知坑点

输出应精炼、无冗余，聚焦模块本身。信息量大时分段条理呈现。

## 验证标准

- [ ] 已读取项目级指南和记忆文件
- [ ] 已确定并定位目标模块
- [ ] 已阅读模块文档和核心源码
- [ ] 若存在依赖，已询问用户并加载指定依赖（或已跳过）
- [ ] 向用户提供了模块上下文摘要

## 反模式

| 借口 | 回应 |
|------|------|
| "没有 AGENTS.md 就不读了" | 按优先级继续查找 README.md，仍没有则概览目录结构 |
| "模块源码太多，懒得看" | 至少阅读入口文件和核心接口文件 |
| "自动推断用户想了解的模块" | 必须向用户确认模块名称和位置 |
| "依赖自动全部加载" | 必须询问用户确认，且由用户提供路径 |
| "子 agent 也深入读源码" | 子 agent 只读指南文件和模块文档，不深入源码 |
