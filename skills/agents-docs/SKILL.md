# 文档与注释分层规范（agents-docs）

本技能定义文档与代码注释的**分层归属约定**，供写作、评审场景与其他技能引用。

要解决的问题：AI 产出效率高，倾向把决策过程、推导细节、调研证据就地写入文档和注释，导致每篇文档、每个文件都长成「大杂烩」——想找结论的人被迫读完整个推导过程。本规范的核心手段是**禁写清单**：每类文档/注释明确规定不允许出现什么。

## 触发场景

- 撰写或更新设计文档、决策记录、架构文档、调研文档
- 评审 AI 生成的文档或代码注释
- 文档/注释明显膨胀，需要瘦身重构
- 新项目需要建立文档体系

## 核心原则

1. **按变化速度分层**：决策依据最稳定，当前结构次之，实现细节最不稳定。每层只承载自己稳定级别的内容，快变内容不污染慢变层。
2. **规范单点维护、被引用**：通用规范集中在技能里，不复制进各项目的 AGENTS.md（见「与 AGENTS.md 的关系」）。
3. **禁写优先于模板**：模板约束不了 AI 的表达欲，「这里不许写什么」才可以。
4. **文档只承载当前态，历史归版本控制**：仓库里的文档永远描述「现在」，不兼任历史记录——版本控制（git）才是那个 append-only 日志，查看历史内容通过版本控制回溯。删除当前态内容前，先把仍有长期价值的部分沉淀到对应类型的文档。

## 文档类型

| 类型 | 典型位置 | 写什么 | 禁写什么 | 更新方式 |
|---|---|---|---|---|
| 决策记录 | `docs/decisions.md`、`docs/<主题>/decisions.md` | 结论、被否决项及否决理由、决策背景 | 机制推导过程、实现细节、证据原文（一律链出）；已失效的旧决策 | **只留当前生效决策**：推翻旧决策 = 就地改写为新结论（仍有约束力的否决理由保留）；依附对象消亡的条目直接删除。历史由 git 承担 |
| 架构概述 | 架构文档、README 架构章节 | 当前结构、模块职责、耦合方向、不变量/红线 | 历史演变、决策过程（链出到决策记录） | 随重构**重写**，不留旧结构遗迹 |
| 调研/事实 | `docs/<主题>/` 调研文档 | 外部系统/数据源的事实、证据、证据等级 | 「我们怎么做」（属决策记录）；原始材料（数据 dump、日志、素材清单） | 证伪即**改写**为当前结论，旧结论由 git 保留；调研发现被决策消费后，长推导压缩为一行结论 + 证据指针 |
| 计划 | `docs/plans/` | 本次改动的目标、方案、文件清单、验证方式 | 长期有效的知识（删除前沉淀到对应类型） | **执行中间态，完成即删**——删除前把其中有长期价值的结论沉淀到决策记录/架构概述，不留存、不归档 |

决策条目的形态：**结论 + 否决项 + 理由 + 指向证据所在文档的链接**（指针只指到文档级，见「分层引用协议」）。决策记录应薄到能一口气读完——它服务的场景是「将来想推翻某个决定时，快速知道当初否决过什么」，机制细节一律链出到架构概述或调研文档。

## 命名约定

命名的职责是让读者在看到正文前就知道文档类型与读者场景：

1. **类型固定的文档用固定名**：决策记录固定为 `decisions.md`（按主题分子目录时同名），计划固定在 `plans/` 目录下按改动命名——类型由名字/位置直接表达。
2. **主题类文档按主题命名**：调研、架构类文档一个主题下有多份，文件名保持主题词，类型由文档导航的说明标注，不把类型塞进文件名。
3. **全小写 kebab-case**：统一命名风格（如 `combat-model.md`，不写 `ASSETS.md`）。
4. **流程类文档（inbox / TODO / 踩坑等）按功能自明命名**，不受 1k 行触发线约束——它们是工作台而非知识层，用读者检验管理即可。

## 注释类型

| 类型 | 内容 | 处置 |
|---|---|---|
| 规则注释 | 契约、不变量、机制规则 | 留在代码，精炼为规则陈述 |
| 陷阱注释 | 语言/框架的行为坑 | 留在代码，同时沉淀到项目踩坑文档 |
| 决策证据 | 决策过程、调研引用、定案历史（如「实机观察 + 某数据通道佐证」「某次对号定案的原版语义」） | **搬走**：结论理由进决策文档，证据原文进调研文档；代码里最多留一句指向文档的指针 |

**检验标准**：重构这段代码时，这条注释还需要跟着改吗？规则注释与陷阱注释不随实现漂移；需要跟着改的实现细节描述和会过期的证据引用，都属于搬走对象。

## 分层引用协议

指针方向**单向**：代码注释 → 决策文档 → 调研文档。

- 代码注释只写规则本身，需要溯源时加一句指针（如「依据见 docs/xxx/decisions.md」）。
- 决策文档引用调研文档作为证据来源。
- **指针只允许指到文档级，禁止指到条目级**：条目会随规模控制被删除，条目级指针必然悬空；文档在当前态模型下长期存活，且条目真被删时读者打开文档找不到、自然转查 git 历史，是优雅降级。
- **调研文档不引用代码符号**（类名、函数名、文件路径）——符号随重构漂移，写死就变成每次改名都要到处对账。例外：目录地图类文档（AGENTS.md 导航、目录结构），指路是它的职责。

## 规模控制

决策记录与调研文档天然只增不减。

**触发线与决策权**：文档默认规模 **1k 行以内**，超过即进入规模控制流程。1k 行是触发线不是目标线——超限不等于必须删回 1k 行，合理超限（如事实速查类文档，读者场景明确）可以保留，项目可用根 AGENTS.md 自定义章节声明例外。**删哪些章节由人决定**，AI 不擅自删。

流程：

1. **触发**：文档超过 1k 行（交付前自查或评审时发现）；
2. **AI 出分析报告**：按段落列出候选瘦身对象及理由——类型不纯（混入了别的层）、已失效（依附对象消亡）、原始材料混入、无读者场景；**只出清单，不动手**；
3. **人拍板**：决定删哪些、留哪些、哪些需要换种写法（如推导压缩为结论 + 指针）；
4. **删除前沉淀检查**：被删内容里仍有长期价值的部分先沉淀到对应类型；
5. **独立提交**：本次规模控制单独一个 commit，提交信息写明删了什么、为什么——这是「历史归 git」能成立的前提。

日常写作纪律（不触发流程时也遵守）：

1. **历史归 git**：所有文档只承载当前态，删除的内容靠版本控制回溯。前提纪律：**文档变更独立提交，提交信息写明「什么决策/事实变了」**——否则 git 考古成本高于文档内留遗迹。
2. **删除前先沉淀**：计划删除前沉淀结论；被推翻的决策改写前，把仍有约束力的否决理由保留进新条目——防止将来有人/AI 重新提议早已被否决的方案。
3. **原始材料不进文档**：数据 dump、日志、素材清单留工程外或工具产出目录，文档只存结论 + 证据摘要 + 证据等级。
4. **消费即提炼**：调研发现被决策消费后，长推导压缩为一行结论 + 证据指针。调研期文档可以长，进入稳态后收敛为事实速查。
5. **读者检验**：每类文档问「谁、在什么场景读它」——决策记录的读者是想推翻决定的人，调研文档的读者是查证事实的人；没有读者场景的内容即删。

## 与 AGENTS.md 的关系

AGENTS.md 是**地图不是规则书**：只放目录结构、文档导航，以及项目特有的红线。

- 通用规范（本文件的内容）一律通过引用本技能生效，**不复制**进任何项目的 AGENTS.md。
- 项目特有的例外与红线（如「决策文档必须中文」「某目录豁免本规范」）以自定义章节留在根 AGENTS.md。
- 文档导航登记文档时，建议在说明中标注其类型（决策/架构/调研/计划），让读者在点进去之前就知道该带着什么预期读。

## 写作检查清单

落笔前与交付前各过一遍：

- [ ] **类型判定**：每段内容已判定归属类型；判不出类型的内容不写
- [ ] **命名约定**：固定类型用固定名；主题文档按主题命名；全小写 kebab-case
- [ ] **决策记录纯度**：条目含结论 + 否决项；机制推导与证据已链出，未就地展开；已失效的旧决策已删除
- [ ] **架构概述纯度**：不含历史演变与决策过程，描述的是当前状态
- [ ] **注释纯度**：代码注释只有规则与陷阱，无决策过程、无证据引用
- [ ] **指针单向且只到文档级**：引用方向为代码 → 决策 → 调研；指针不含条目级定位；文档中无代码符号引用（地图类除外）
- [ ] **当前态**：文档只描述「现在」，历史内容不在文档内留遗迹；文档变更独立提交且提交信息写明变更内容
- [ ] **规模检查**：文档 ≤1k 行；超限的已走规模控制流程（AI 报告、人决策、独立提交）或已在根 AGENTS.md 声明例外
- [ ] **计划闭环**：已完成的计划文档已删除，删除前长期有效的知识已沉淀到对应类型
