# SSH 上下文获取

读取用户 `~/.ssh/config` 文件，解析其中的远程主机配置，输出结构化的主机连接信息表。

## 触发场景

- 用户需要查看本地配置的 SSH 主机列表
- 用户准备通过 SSH 连接、部署或操作远程主机
- 当前任务需要基于 SSH 配置推断主机地址、用户名或端口
- 用户问"我有哪些 SSH 主机"、"SSH config 里配了哪些机器"等

## 执行步骤

### 步骤1：确认读取

`~/.ssh/config` 属于用户敏感配置，读取前必须向用户确认。说明读取范围：

- 只读取 `~/.ssh/config` 文件本身
- 不读取任何私钥文件（如 `id_rsa`、`id_ed25519` 等）
- 只解析连接参数，不输出或泄露密钥内容

若用户不同意，停止执行并说明原因。

### 步骤2：读取配置文件

读取 `~/.ssh/config`（或用户指定的其他路径）。

### 步骤3：解析主机条目

按 SSH config 语法解析 `Host` 块，提取以下常用字段：

- `Host`：配置别名
- `HostName`：实际主机地址（IP 或域名）
- `User`：登录用户名
- `Port`：SSH 端口（未指定时默认为 22）
- `IdentityFile`：身份密钥文件路径（仅列出路径，不读取内容）

注意：

- 忽略通配符主机（如 `Host *`）中的默认值，除非没有更具体的匹配
- 若配置中包含 `Include` 指令，可选是否递归读取被包含文件；默认只处理主文件
- 不解析、不输出 `ProxyCommand`、`LocalForward` 等高级字段，除非用户明确要求

### 步骤4：输出主机信息表

以表格形式输出解析结果，便于后续任务引用：

| Host 别名 | HostName | User | Port | IdentityFile |
|---|---|---|---|---|
| example | 192.168.1.10 | admin | 22 | ~/.ssh/id_rsa |

输出后询问用户：

- 是否需要针对某台主机执行后续 SSH 操作
- 是否需要读取被 `Include` 引入的其他配置文件

## 验证标准

- [ ] 已向用户说明读取范围并获得同意
- [ ] 已读取 `~/.ssh/config`
- [ ] 已解析并输出至少 Host 别名列表
- [ ] 未读取或输出任何私钥文件内容
- [ ] 输出结果以表格形式呈现，便于后续引用

## 注意事项

- 私钥文件只列路径，严禁读取其内容
- 若 `~/.ssh/config` 不存在，告知用户并询问是否指定其他路径
- 若文件内容为空或无 Host 条目，输出空表并说明
- 该 skill 只负责读取和展示配置，不直接执行 SSH 连接或命令
