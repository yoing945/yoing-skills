# 项目上下文获取

快速了解当前项目的架构、规范、记忆和约束，为后续工作建立上下文基础。

## 触发场景

- 用户首次在当前项目中发起对话
- 用户明确要求了解项目架构、规范或上下文
- 用户问"这个项目是什么"、"项目结构是怎样的"等类似问题
- 当前任务需要基于项目特定约定执行

## 执行步骤

### 步骤1：读取项目指南文件

按优先级查找并阅读项目指南：`AGENTS.md`(或`CLAUDE.md`) → `README.md` → 概览项目目录结构。

### 步骤1.5：加载关联项目上下文（可选）

如果在步骤1中读取到的 `AGENTS.md` 包含"关联项目"章节，按以下流程处理：

1. 提取关联项目名称列表
2. 向用户提问："本项目关联以下项目：[项目A, 项目B, ...]。需要加载哪些的上下文？请按 `项目名: 本地路径` 的格式列出，不需要则回复'无'。"
3. 用户指定路径后，为每个项目并行启动子 agent
4. 子 agent 只执行简化版上下文获取：进入指定路径，按步骤1的优先级读取该项目的 `AGENTS.md`(或`CLAUDE.md`) / `README.md`，返回该项目的上下文摘要（不读取记忆文件）
5. 主 agent 收集各子 agent 的输出，留待步骤3整合

若用户回复"无"或 AGENTS.md 中无"关联项目"章节，跳过此步骤。

### 步骤2：读取项目记忆文件

查找并阅读项目级记忆文件（这些文件通常包含用户偏好、项目约定和历史上下文）：

1. 查找 `.agents/`、`.claude/`等 目录下所有文件，尤其是 `memory/` 子目录中的内容和该目录下的`AGENTS.md`
2. 若记忆文件过多，优先读取最新修改的文件；若内容过长，优先读取摘要性内容

### 步骤3：整合上下文并输出摘要

基于以上读取到的信息，向用户输出一份简洁的项目上下文摘要，包含：

- **项目概述**：一句话描述项目是什么
- **技术栈**（如有）：主要语言、框架、工具
- **关键规范**：编码风格、目录约定、命名规则等
- **项目结构**：顶层目录及其职责
- **记忆要点**：用户的特殊偏好、历史决策、注意事项
- **文档索引**：项目中值得参考的重要文件列表
- **关联项目上下文**（如有）：已加载的关联项目名称、路径及其核心上下文摘要

输出应精炼、无冗余，只提供 AI 执行后续任务所需的必要上下文，不展开详细设计。信息量大时（超过10000TOKEN）分段条理概括呈现。

## 验证标准

- [ ] 已尝试读取根目录的 `AGENTS.md` 或 `CLAUDE.md` 或 `README.md`
- [ ] 若 AGENTS.md 包含关联项目，已询问用户并加载指定项目（或已跳过）
- [ ] 已检查 `.claude/` 和 `.agents/` 下的记忆文件
- [ ] 向用户提供了整合后的上下文摘要（含关联项目，如有）

## 反模式

| 借口 | 回应 |
|------|------|
| "没有 AGENTS.md 就不读了" | 按优先级继续查找 README.md，仍没有则概览目录结构 |
| "记忆文件太多，懒得看" | 至少读取最新的 3 个记忆文件 |
| "输出详细的项目文档" | 只输出摘要，详细文档让用户自行查阅原文 |
| "关联项目自动全部加载" | 必须询问用户确认，且由用户提供路径 |
| "关联项目也读取记忆文件" | 子 agent 只执行步骤1（读指南文件） |
