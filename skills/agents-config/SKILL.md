# 技能配置约定（agents-config）

本技能定义技能配置文件的**统一读写约定**，供其他技能引用；本身不含业务逻辑。
技能需要配置项时**引用本技能**，不要在各自 SKILL.md 里重复定义读取规则。

## 两个配置文件

| 文件 | 职责 | 是否进 git |
|---|---|---|
| `.agents.config.yaml` | 共享配置（仓库共用的配置） | **进 git** |
| `.agents.config.local.yaml` | 个人本地配置（个人路径、测试凭据等） | 不进 git（`*.local.yaml` 已 gitignore） |

入库原则：进 git 的只放可共享的内容；个人性、测试性内容一律放 local。
**不要在任何进 git 的文件里放高敏凭据**（密码、私钥、签名密钥等）。

## 目录级作用域（核心约束）

- 配置的作用域是**目录**，不是项目：技能在目录 D 运行时，只读取 `D/.agents.config.yaml` 与 `D/.agents.config.local.yaml`。
- **不向上查找**：目标目录没有配置、或配置中没有自己的域，就按无配置处理（回退默认值或询问用户），绝不从父目录继承。
- 每个目录至多一对配置文件；文件位置即作用域，目录是自包含模块，配置跟着目录走，不同目录的配置互不影响。

## 文件结构：唯一规则是"顶层键 = 技能域"

顶层键为技能域（domain），**域名与技能名完全一致，不使用简写**（如 `agents-guide`，不用 `guide`）。这是本约定**唯一**定死的结构规则：

```yaml
# .agents.config.yaml
example-skill1:
  - name: config1
    description: xxx

example-skill2:
  - name: config1
    skill-self-key: xxx
  - name: config2
    skill-self-key: xxx
```

- **域内完全自治**：域内是列表还是映射、用什么键标识条目、有哪些字段，都由消费技能自行定义，并在其 SKILL.md 中说明。本约定不做任何规定。
- 技能只需要在配置文件中找到属于自己的域，取走所需配置即可，**其他域一概不管**。
- 某个域内容非法只影响该域对应的技能，不拖垮其他技能。

## 覆盖语义：技能自治

agents-config 只定义两个文件层的**职责**（共享层 vs 个人本地层），不规定 local 如何作用于共享层。

- 替换、合并还是扩展，在什么粒度上作用（整域、条目、字段），由**消费技能自行定义**，并在其 SKILL.md 中明确说明。
- 唯一要求：语义必须**明确、可预期**，用户读完技能文档能推断出最终生效的配置。
- 文件自身解析失败（YAML 语法错误）时，按无该文件处理并提示用户。

## `--init` / `--init-local` 行为约定（使用方技能遵守）

- `--init`：在目标目录生成/补充 `.agents.config.yaml` 中本技能的域（共享层）。
- `--init-local`：在目标目录生成/补充 `.agents.config.local.yaml` 中本技能的域（个人本地层）。
- 文件不存在 → 生成含本技能域的骨架，本技能域填最小示例。
- 文件已存在 → **不覆盖**：已含本技能域则提示已配置；缺少则输出待追加的 YAML 片段，请用户合并。
- 各技能只负责自己域的初始化，不动其他域。
- 骨架内容保持**中性**：共享层模板不放个人偏好，个人偏好由 `--init-local` 引导写入 local 层。

## 域文档规则

本技能不维护集中登记表（易漂移）。域级信息各自单点记录：

- **用途**：域内条目的 `description` 字段（文件即文档）；
- **使用方与结构**：消费技能的 SKILL.md 说明自己依赖的域及其内部结构、覆盖语义。

新增域前，先 grep 技能目录确认无同名冲突，再按「入库原则」选择所在层。

## 验证标准

- [ ] 读取配置时只在目标目录查找，不向上继承
- [ ] 域内结构与覆盖语义由消费技能自治，并在其 SKILL.md 中明确说明
- [ ] `--init` / `--init-local` 不覆盖已有文件，不改动其他技能的域
